# newBeing — 界面结构规划

依据：PRTS Design（MooncellWiki/prts-design，取自官网 CSS + torappu 解包）与
腾讯游戏学院《明日方舟》UI 拆解。所有结构决策都对得上上游的类名与用法。

---

## 一、方舟的信息架构（调研结论）

### 1.1 Tab 的三种变体，各管一个层级

| 类 | 用途 | 视觉标记 |
|---|---|---|
| `.ak-tabs` | 页内主分区 | 下划线 + **6×6 三角角标**（仅当前项，`::before`） |
| `.ak-tabs--block` | 游戏内块状标签 | 选中项**黑白反转**（`bg: var(--ak-fg)`，`color: var(--ak-bg-canvas)`） |
| `.ak-tabs--vertical` | 长内容多分区 | 左缘 3px 条；可带第二行小字 |

`.ak-tabset--left` = 竖向标签列 + 右侧面板，`grid-template-columns: max-content minmax(0,1fr)`。

### 1.2 装饰语言（11 类，各有明确用途）

| 类 | 作用 |
|---|---|
| `.ak-stripes` | -45° 斜纹；`--strong/--warning/--danger/--hazard` 四档 |
| `.ak-stripe-edge` | 8px 黄黑斜纹贴边 |
| `.ak-halftone` | 网点 + 渐隐遮罩（`mask-image`），可 `--l` / `--full` |
| `.ak-blue-band` | 蓝底白字 + 网点，区块标题 |
| `.ak-corner` | 10px（`--lg` 18px）三角角标，左上/右上，可黄/红 |
| `.ak-brackets` | 14px 四角括线，框住读数区 |
| `.ak-inverse` | 黑白反转 |
| `.ak-chevrons` | `»` 动作指引，hover 右移 3px |
| `.ak-en` | 大写拉丁装饰字 |
| `.ak-glyph` | 白色线稿图标 |
| `.ak-bilingual` | 中英双语排布 |

**明确不做**：无切角（`.ak-chamfer`）、无斜切（`.ak-skew`）、无 45° 斜边、无辉光。

### 1.3 `.ak-stat` 的结构

```
padding 12px 16px
border 1px
border-top-width: 2px + border-image: linear-gradient(accent 2px, border 2px)  ← 顶部青色条
label: 600 overline / uppercase / tracking .14em / fg-muted
value: 700 h2 / tabular-nums / fg
delta: xs / --up / --down
```

## 二、层级规划

### L1 — 顶栏（4 个模式）

用 `.ak-tabs--block` 的语义：黑白反转标记当前模式。
这是「系统」层，不是内容层。

```
MARKETS   RESEARCH   BACKTEST   REPLAY
```

### L2 — 每个模式内部（竖向 tab，`.ak-tabs--vertical`）

| 模式 | L2 分区 | tab 数 |
|---|---|---|
| Markets | 无（交易台，四块并列） | 0 |
| Research | 参数 / 源码 / 说明 | 3 |
| Backtest | 指标 / 交易 / 实验 / 日志 | 4 |
| Replay | 会话 / 账户 / 订单 | 3 |

### L3 — 面板内部

**不设 tab**，内容直排。方舟的做法：面板内部靠分隔线与底色阶梯分组，
不叠加第三层 tab。

## 三、Dock 按模式拆分

现状：5 个标签在所有模式都显示 → 5 × 4 = 20 个无效组合。

改为：

| 模式 | Dock 标签 | 数量 |
|---|---|---|
| Markets | Positions / Orders | 2 |
| Research | Experiments / Execution | 2 |
| Backtest | Metrics / Trades / Experiments / Execution | 4 |
| Replay | Session / Orders | 2 |

总计 **10 个**，每个都只在有意义的模式下出现。

## 五、装饰强度：克制

只用三处：

1. **当前 tab 的三角角标**（`.ak-corner`，6px）—— 标记当前，不增加噪音
2. **危险/警告状态的斜纹**（`.ak-stripes--warning`）—— 仅 stale / replay 隔离
3. **面板头的 4px 色条**（已实现）+ `.ak-stat` 顶部 2px 条 —— 分区感

**不用**：大面积网点、四角括线、双语标题、蓝底 band。

理由：这是交易工具，读数优先。装饰只用来标记状态与层级，不铺满。

## 六、实施顺序

1. 顶栏改 `.ak-tabs--block` 语义（黑白反转）
2. 右侧检查器改竖向 tab
3. dock 改竖向 tab + 按模式拆分内容
4. L2 分区（Research / Backtest / Replay）
5. 三处克制装饰

## 七、状态与可读性（2026-11 增补）

交易台最重要的读数是「这个数字是不是活的」。这一节固定这类判断的表达方式。

### 7.1 颜色只表达两件不同的事

| 信号 | 语义 | 用在哪 |
|---|---|---|
| `--c-accent`（青） | 选中 / 焦点 / 开启 | tab、指标开关、焦点环 |
| `--c-warn`（琥珀） | **数据降级**：行情、盘口、账户陈旧或不可用 | 自选横幅、盘口状态块、数据戳、图表错误层 |
| `--c-up` / `--c-down` | **钱的方向**：涨跌、盈亏、买卖 | 价格、K 线、uPnL、涨跌胶囊 |

数据不可用不是危险，不要用红色。红色留给可能造成资金损失的状态（委托被拒、未确认委托）。
琥珀降级块统一使用 `.stripe-edge`（8px 斜纹贴边）+ 琥珀文字 + 句子大小写，
自选、盘口、图表三处形状一致。
图表请求失败时仍覆盖整个绘图区；标题只说明行情不可用，原始诊断收在可展开详情中，重试操作保持可见。这样保留排障信息，又不让技术错误占据图表主位。

**降级面一律从 `--c-warn` 推导，不写死 Tailwind 琥珀色阶。**
三套写死的色阶（`amber-500/10` + `amber-400`、`amber-950/40` + `amber-300`）看起来同义，
实际是三个不同颜色，改令牌时不会一起动。现由四个类承载：
`.degraded-panel`（块）、`.degraded-strip`（窄条）、`.degraded-banner`（顶栏横幅）
及其 `.degraded-caption` / `.degraded-chip` / `.degraded-dot` 子件。
小字标题用 `color-mix(--c-warn 62%, #fff)` 提亮以保住对比度（正文 8.09:1、标题 10.78:1）。

### 7.2 可读性下限

- **文字对比度**：最小字体档 `--c-fg-4` 取 `#808b9d`。它在最亮的六个表面 token 上都 ≥ 4.5:1；
  更暗的 `#64748b` 在面板头上只有 3.3:1，全部 9–11px 标签都不合格。
- **字号下限** `--t-micro: 10px`。数据戳、状态胶囊、免责声明都用这一档，不再出现 8px / 9px。
  顶栏的 `LAST` 标签与 24H 三块统计的标签都曾写死 9px，现已升到这一档。
- **不透明度不用于承载信息的文字**。stale 的价格、数据戳、免责声明一律保持满不透明度，
  由文字本身和琥珀色说明状态；`opacity` 只留给装饰（拖拽把手、分隔符、hover 提示）。

### 7.3 层叠规则（踩过的坑）

`globals.css` 的规则写在 `@layer` 之外，而 Tailwind 语义类在 `utilities` 层里。
**未分层规则永远赢过分层规则**，与选择器特异度无关。所以：

- `.summary-strip span { font-size: 9px }` 曾经压掉了价格占位的 `text-2xl`，让占位只有 9px，
  行情到达时价格从 9px 跳到 26px（真实的布局抖动）。
- 组件里需要覆盖这类规则的尺寸/颜色时，用**自己的类**（`.summary-placeholder`、
  `.data-stamp.is-stale`、`.summary-change[data-direction]`），不要用工具类。

### 7.4 动效

- 价格闪烁只在 `prefers-reduced-motion: no-preference` 下播放；数字本身已经是主要信息。
- 加载骨架只表示「请求在飞」；请求失败后立刻收敛为 `—`，不再无限脉冲。
- 状态切换不做逐项淡入淡出；一个面板只保留一个状态层。

## 八、工具类与设计令牌的接线（2026-11 增补）

### 8.1 字体只在主题里接一次

`@theme { --font-mono: var(--f-mono); --font-sans: var(--f-body); }`

组件里有 239 处 `font-mono`。改动前它们是 Tailwind 的默认栈
（`ui-monospace, SFMono-Regular, Consolas`），也就是同一张屏上有三分之一的数字
没用到 JetBrains Mono 的等宽字形。逐个改 class 不现实，也不该改；把主题变量指过去，
一处生效。**新增字体族时改主题，不要新增工具类映射。**

### 8.2 加载只有一种画法

- 面板内、按钮内、弹窗内的等待：`<LoaderCircle className="spin" size={12} />` +
  紧邻的 11px 说明文字。图表画布内的等待用 14px。
- 不再使用 `AkSpinner`（菱形）：它自带 110px 尺寸和独立配色 `#18d1ff`，
  在第 6 节已经收敛掉。**一个屏幕最多一个"在进行中"的图形。**

### 8.3 滚动视口必须切在行的边界

`.dock-content` 的可视高度是 205px。指标条以前是 `minmax(118px)`，在默认停靠宽度下
挤成 2 列 × 3 行 = 180px，最后一行被视口切掉半个单元格。改成 `minmax(104px)` 后是
3 列 × 2 行，整块落在视口内。**新增格子/行时先量：格子总高必须 ≤ 视口，或者整块可以滚动。**
同样的道理适用于 `.dock-tabs`：五个标签 481px 塞进 415px 的停靠区，
以前 `overflow: visible` 把最后一个标签切在面板外且**无法点击**，现在是横向滚动 + 右缘渐隐。

### 8.4 一个状态只说一次

顶栏曾同时出现 `TICKER OFFLINE / AWAITING FEED / DELAYED`——三个句子描述同一件事。
行情失败时时间戳槽位留空，状态交给错误槽和 feed 胶囊；没有失败且没有时间戳时才写
`AWAITING FEED`。**同一条件在相邻位置出现第二次就是噪音。**

## 九、价格只有一种写法（2026-11 增补）

同一个 BTC 报价曾经同时以 `87,497.24004`（顶栏、持仓表）和 `87,497.24`（图表图例）
出现在一屏上——三份各自实现的 formatter。

`apps/web/src/lib/price-format.ts` 的 `formatQuotePrice()` 是唯一实现，按量级取位：

| 量级 | 小数位 |
|---|---|
| ≥ 1 | 2 |
| ≥ 0.01 | 4 |
| ≥ 0.0001 | 6 |
| 其余 | 8 |

顶栏、自选、图表图例、持仓表都调用它。**新增显示价格的位置时调用它，不要写 `toLocaleString`。**

### 9.1b 规模不是价格：数量有另一条梯子

盘口深度与成交明细里的**规模**是基础资产的数量，不是报价，精度比报价细。
`formatSize()` 是规模的唯一实现：

| 量级 | 小数位 |
|---|---|
| ≥ 10000 | 2 |
| ≥ 0.0001 | 4 |
| 其余 | 8 |

`0.14` BTC 印作 `0.1400`，`866.14` 印作 `866.1400`（不截断），
尘埃规模 `0.00001234` 印作 `0.00001234`（不归零）。
金额（权益、盈亏、手续费）另有 `amount()`，保留账本精度，不走报价梯子。

### 9.1c 盘口与成交带：表头和数据行共用一条轨道
盘口 `PRICE (USDT) | SIZE`，成交带 `PRICE | AMOUNT | TIME`。
表头与数据行**必须**共用同一个 `grid-template-columns`：
成交带曾经是三列表头配两列数据行，`TIME` 值因此掉到第二行、压在价格上，
表头也和数据列错位。

深度条画在规模列内（`position: absolute`，右对齐），长度是相对最大档的规模占比，
硬边标出量级边界。它**不得**盖住价格数字，颜色取 `--c-down` / `--c-up` 方向令牌——
写死红绿会让 deuteranopia 模式下的深度条不随 K 线重绘。

### 9.1d 成交额按量级取单位
24H 成交额曾经硬编码除以一百万并固定加 `M`：清淡的市场印出 `0.00M`，
繁忙的市场印出 `1420.00M`。`formatCompactAmount()` 让单位跟着量级走：
`820.00K`、`171.70M`、`1.42B`，不足一千则不带单位（`842.50`）。

### 9.1e 增减与比例是两种数

`+54.55%` 曾经印在**胜率**上——胜率是比例，不是变化量，正号让 54% 读起来像"涨了 54%"。
同一个胜率还分别以 `+54.55%`、`55%`、`54.5%` 三种精度出现在结果条、简报卡与扫参表。

现在两个函数分管两类数，都取分数、都保留两位：

| 函数 | 用途 | 输出 |
|---|---|---|
| `formatPercentChange()` | 收益、回撤等**有方向的增减** | `+2.87%` / `−5.72%`；零值无符号 |
| `formatRate()` | 胜率等**无方向的比例** | `54.55%` |

指标条的箭头同理：`↗`/`↘` 只给变化量（收益、回撤），夏普、盈利因子、胜率是水平值，
只有色调没有箭头。箭头与正负号同时存在是有意的（§7.1：方向不靠颜色单独承载）。
本轮之前还有三份重复的百分比实现（结果 dock、评估面板、扫参面板），已收敛到这两个函数。

### 9.2 主操作按钮的对比度

`#0284c7` 上的白字在 11px 时只有 4.09:1。降到天空色一档 `#0369a1`（5.9:1），
hover 用 `#075985`。色相不变，层级不变。

### 9.3 用 fixture 看真实状态

交易所不可达时，空态/错误态可以验证，但布局的很多问题只在有数据时出现
（小数位不齐、指标条换行、图表图例宽度）。本地验证方法：

```sh
NEWBEING_E2E_FIXTURES=1 NEWBEING_DATA_DIR=E:/Temp/newbeing-design-db pnpm dev
```

fixture 只对 Binance 生效（`apps/web/src/lib/market-adapter.ts`），进页面后把
交易所切到 **Binance Spot**，即可得到确定性的行情、盘口、成交与衍生品报价。
**永远不要用默认数据目录跑 fixture 浏览器验证。**
